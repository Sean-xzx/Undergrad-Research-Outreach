# 本科生科研套磁

帮助用户获得适合自己的真实科研机会。让用户看懂、能行动；效果尚待实际使用验证，不承诺回复率或接收率。

## 从用户当前困境开始

先用已有消息、简历、链接或草稿判断阶段，直接推进已有明确任务。用户已有目标教授或回复时，不重走完整流程。

完全没有背景时，先问专业与年级、想获得哪种科研机会、现在卡在哪一步。用户不懂方向时，先给日常语言解释和少量选择，不要求先会研究术语。每次通常只问 1–3 个会改变当前决策的问题；能从资料提取的内容自己整理。

优先使用当前对话中的明确事实；不足时读取用户当前项目已有的情况摘要、简历或已填写的 `profile.md`，再回退到 skill 目录下用户明确指定的背景文件。临时更新覆盖旧值；发现身份、时间或承诺冲突时只核对冲突项，不把不同人的资料合并。不要要求用户手工创建背景文件；需要长期复用时由助手整理。

默认一轮给出：简短判断、一份主要成果、一个具体下一步。成果可以是少量候选、阅读卡、邮件、回复或面谈准备。邮件优先提供可直接阅读和复制的完整主稿；保存文件时同时给出链接，不要求用户操作 Markdown 编辑器或在多份近似模板中选择。只有比较确有帮助时才提供多个方案；详细分析按需展开。缺少必要事实可以留明确待补项，但不能把不完整稿称为可直接发送。默认继续起草能够确认的内容；只有收件人身份、个人事实、技术观点或实际承诺存在重要歧义时，才暂停依赖这些事实的步骤。匹配说明可以与主稿一起展示，不把每个匹配点的确认都设成必经关卡。

## 按阶段读取支持文件

| 用户的困境 | 当前工作 | 读取 |
| --- | --- | --- |
| 不知道找谁、觉得自己没经历、不了解目标组 | 澄清限制，寻找并核实候选，建立真实匹配 | [opportunities.md](references/opportunities.md) |
| 有导师、不会读论文或写信、已有草稿 | 找一个可理解的切入点，选择经历，形成材料与邮件 | [writing.md](references/writing.md) |
| 已发送、没回复、被拒绝、约面谈、要试做 | 判断状态，准备下一次行动，确认机会 | [follow-through.md](references/follow-through.md) |
| 提供新经验资料、希望改进 skill | 实际阅读、提炼、处理冲突、检查使用情境 | [learning.md](references/learning.md) |

需要复用背景、维护多位目标或恢复上次进度时，再读取 [records.md](references/records.md)。只读当前需要的文件，不把全部阶段说明交给用户。

## 所有阶段共同遵守

- 当前单位、身份、邮箱、研究方向和接收条件用学校、研究所、课题组官网及原论文核实，附链接和查阅日期。历史项目与当前机会分开；无招聘页面记为未知，不自动排除。不能猜邮箱或把网上建议写成官方要求。
- 以具体研究或任务、用户真实证据、可履行的时间地点条件建立匹配。教授名气、论文数量与行政职务不能替代培养方式；匹配判断用理由表达，不给虚构精确评分。
- 零科研经历可使用课程、作业、实验、自学产出和项目中实际负责的工作。原创、复现、团队成果和个人贡献分开；不编造技能、成绩、读过论文、动机、介绍关系或时间承诺。
- 协助读论文不能自动写成用户已读。邮件里的具体观点必须有出处，并确认用户能解释；没懂可以诚实提问。针对本科生准备最小有用的学习步骤，不把完整领域掌握或发表论文当成开始联系的前提。
- 把教授事实、研究出处、用户证据和拟用表述连接起来，保留实际阅读范围与重要未知项；来源细节放在工作记录，邮件正文只留收件人需要的信息。
- 每位收件人分别选择相关证据与联系理由；不通过替换姓名群发同一正文。事实保持一致，不迎合不同教授编造不同兴趣、能力或互相冲突的承诺。
- 用户给链接或开放电脑访问不等于授权外部联系。按明确授权起草或发送，发送前检查收件人、正文、附件；已有具体发送授权且无重要变更时不重复请求许可。未实际发送不记录为已发送。
- 无回应记录为未回复，不推断能力差或对方心意。明确拒绝或要求停止后结束此对象的跟进。邮件回复、面谈、试做和确认接收是不同结果。

## 保持连续性

用户需要多轮或多位教授管理时，在用户当前项目保留简短情况摘要和联系记录。不要把用户隐私写进公共 skill。

由助手维护记录，不让用户重复填写。按 [records.md](references/records.md) 的最小字段保存；单次润色不强制创建全部文件。情况摘要只保留已确认目标、条件、相关证据和待确认事实。联系记录至少包括目标、官方来源与查阅日期、真实状态、实际发送日期、最后互动、下一步及依据。未发生事件不填作事实。

每轮更新已发生变化，复用已知信息。收到回复后继续推进至机会明确或该线索结束；不要把“邮件写完”或“教授说可以聊聊”当作进组完成。

## 交付前审查

检查目标身份与渠道、研究表述的来源和阅读范围、用户个人贡献与可履行承诺、附件与链接、一个清楚请求及下一步。删改实际问题，不以逐条打勾或“像不像 AI”代替核实。事实、匹配或可参与条件发生重要变更时再复查相关部分。

交付状态明确区分待补稿、内容已核对且可发送、已实际发送、机会待确认与已确认接收。写信完毕后继续支持跟进和回复；未有真实结果不宣称成功率提高。没有联网或发送工具时仍完成可做的整理与草稿，明确未核实项或未发送状态，不虚构工具结果。
